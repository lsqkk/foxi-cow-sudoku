# 佛系消消消 · 纯净版（数独 × 扫雷 复刻）

一个纯前端、无限畅玩、难度可调的《佛系消消消》复刻版：没有体力值、没有广告、没有内购，
关卡由前端即时生成（**保证唯一解、保证纯逻辑可解**），并且内置一套「真实难度标定」工具，
用来把**地图生成难度**和**玩家体感难度**对应起来。

> 玩法原型参考：桌面上的两张游戏截图（10×10，第 1567 关）。原版的三条规则：
> ①每种颜色只有 1 头小牛；②每行每列有且仅有 1 头；③小牛不能相邻（含斜角）。

## 快速开始

```bash
npm install
npm run dev        # 开发服务器，默认 http://localhost:5173
npm run build      # 产出 dist/（纯静态，可直接丢到任意静态托管/GitHub Pages）
npm run preview    # 预览打包结果
npm test           # 引擎测试（唯一性 / 推理可靠性 / 生成性能 / 可复现性）
SHOW_DIST=1 npm test   # 额外打印难度分布、生成耗时、唯一率等诊断信息
```

## 操作方式（与原版一致）

| 操作 | 效果 |
| --- | --- |
| 单击空格 | 打一个白色 ×（该位置不可能是小牛） |
| 单击 × | 取消这个 × |
| 从格子按住拖动 | 连续打 ×（从 × 开始拖则连续取消） |
| 双击格子 | 放一头小牛 |
| 单击已放的小牛 | 把它拿走 |

放下一头小牛后，它所在的**行、列、同色区域，以及周围 8 格**都会被自动排除 —— 这是最常用的一条规则。

## 已实现的推理技术（提示与难度统计都基于这些）

引擎用「技术阶梯」把每张地图从头解一遍，阶梯按人的思考成本分层：

1. **唯一候选**：某行/列只剩一个候选格，或某颜色只剩一个候选格 → 直接放牛。
2. **颜色被限制在一行/列**：某颜色的所有候选都在同一行/列内 → 该行/列其余格子排除。
3. **整行/列同色**：某行/列的候选都属于同一种颜色 → 该颜色在其它位置的格子排除。
4. **行列同色交会**：某行与某列的候选属于同一种颜色，交会点必是小牛。
5. **同色候选邻域覆盖**：某颜色的候选只有相邻两格/三格（或任意几格），无论放哪一格
   都会排除的公共格子可以排除（对应「两格排除周围、三格排除中间两侧」这类技巧）。
6. **k 单元包含关系**：k 个行/列的候选恰好落在 k 种颜色（或 k 个列/行）内 →
   这些位置被“用满”，其余格子排除（对应原版里“x 种颜色完全被包含在 x 列内”那一类）。
7. **反证 / 排除法（兜底）**：假设某格是小牛，继续推理会走到矛盾（有颜色或行列无处可放）→ 该格排除。
   这是**完备的兜底手段**：只要关卡有唯一解，反复做这件事一定能推到终局。

实测结果：当前生成器产出的关卡 **100% 可以只用 1~6 推完**，几乎不需要动用到反证兜底。

## 难度是怎么定义和可调的

难度分（1~10）主要由**关卡设计**决定，棋盘大小只做 ±10% 的轻微修正（因为 10×10 也可能很简单，
12×13 也可能只是中等）：

```
生成难度 ≈ 平均每头牛的推理成本（用了哪些技术 × 各自成本）
           × 尺寸修正(±10%) × 颜色缠绕度
           + 兜底惩罚（简单逻辑越早卡住、越依赖反证/排除法，就越难）
```

界面上可以同时调 **目标难度 1~10** 和 **棋盘尺寸 5~13**（也可以只用预设：入门/简单/中等/困难/专家/大师）。
“查看关卡信息”会摊开这一关的全部指标：生成难度分、纯逻辑推进率、逻辑步数、颜色大小分布（基尼系数）、
小颜色占比、缠绕度、被限制在一行/列的颜色占比、实际用到的技术统计、以及可复现的关卡码。

### 关于“真正的难度”，请帮我标定

「标定」页准备了 18 关固定的**难度光谱**（尺寸 6~13、设计从极其规整到非常缠绕，种子固定可复现）。
请实际玩一遍并给每关打分（1~5 星 + 标签 + 备注），数据会存在浏览器本地。

玩完之后在「数据」页可以看到：

* **相关系数 r / 秩相关 ρ**：生成难度分 与 你的体感分 的相关性；
* **拟合直线**：体感分 ≈ a × 生成分 + b（附 R²）；
* **特征相关性排序**：小颜色占比、区域大小不均、颜色缠绕度、逻辑步数、最高技术层、
  是否用到反证……哪个最能预测你的真实体感；
* 一键导出 **JSON / CSV**（包含每关的全部指标、用时、错误、提示、你的评分与备注）。

把 CSV/JSON 发我，我就可以据此调整生成参数与难度公式。标定页里的 18 关只是起点，
后面完全可以让生成器“按分数点单”（比如专门生成“你觉得 3 分”的关卡）。

## 引擎实现要点（供 review）

* **地图生成**：随机一个合法小牛布局（每行每列一头 + 互不相邻）→ 划分颜色区域 →
  **唯一性修复** → 逻辑体检。
  * 关键发现：随机分区几乎必然多解（8×8 平均 200+ 个解）。让 **颜色大小不均匀、出现一批 1~3 格的小颜色**
    才是让解唯一的核心（小颜色的“只有一头牛”约束非常强）。所以生成器会先抽一个重尾的尺寸分布，
    再把大颜色塑造成整行/整列或线段，小颜色保持 1~3 格。
  * 对仍然多解的棋盘做**爬山式修复**：取一个“别的解”，把它某头牛所在的格子挪给相邻颜色
    （真解不受影响，那个解立刻作废），优先选择不破坏强线索颜色、且保持区域连通的搬法。
  * 最后一定做**回溯计数校验**：搜到第 2 个解就淘汰该候选；只有唯一解才会上桌。
* **推理引擎**：候选位图 + 单元计数（行/列/颜色），阶梯技术逐层尝试；
  所有推理都是**可靠**的（测试会用真解逐步校验，绝不出现“把真解排除掉”的步骤）。
* **兜底**：反证排除（`refutationDeduction`）与唯一解推演（`solutionHint`），保证唯一解的关卡一定能做到底。
* **可复现**：同一个（关卡号, 难度, 尺寸）或同一个种子一定生成同一张地图，关卡码形如 `n8-1y4y1`。

```
src/
  engine/            纯逻辑引擎（无 UI 依赖，可单独跑测试）
    board.ts         小牛布局、颜色区域造型与尺寸分配
    solver.ts        技术阶梯、反证兜底、唯一性搜索、提示
    difficulty.ts    难度特征、难度分、预设与难度刻度
    generator.ts     生成 + 唯一性修复 + 目标难度匹配
  game/              游戏状态与数据
    useGame.ts       标记/计时/错误/撤销/提示/胜负

    theme.ts         调色板、色盲模式、颜色命名

```

## 与原版的差别（有意为之）

* 无体力值、无广告、无内购，提示不限次数；
* 关卡前端即时生成，可无限玩下去，难度与尺寸都能自己调；
* 额外提供撤销、计时、错误统计、生成指标展示、难度标定与数据导出；
* 保留了原版的观感（配色、圆角格子、白色 ×、小牛 emoji、规则条）与手势操作。

## 已知限制 / 下一步

* 生成器在 12~13 尺寸、极低“小颜色”比例时命中率较低，会退回到更规整的形状（并标记 `unproven`），
  因此极端难度的把关还不够精细 —— 这正是需要你的标定数据来调的地方。
* 难度分目前按“推理技术成本”线性折算，尚未用真实数据回归；标定页就是为了把这一步做实。
* 暂未做：关卡码导入、分享/排行榜、云端同步、音效。
